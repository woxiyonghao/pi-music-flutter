# iPhone 横屏对齐与曲库修复验证

日期：2026-10-25（Asia/Shanghai）

基线：`dev/iphone` a1118d7；界面与功能参考 `dev/ipad` 03d4d8b。

## 完成内容

- 首帧展示横竖屏选择；方向仅在本次进程内保存，进入后没有切换入口，冷启动重新选择。
- 横屏工作台、侧栏、播放控制、DAC、EQ、音色、主题、全屏、扫描及网络服务对齐 iPad，并适配 iPhone 安全区与小屏滚动。
- 自建歌单支持创建、加入和移出曲目；重扫保持曲目 ID 与歌单关联。
- 删除内置演示曲目和音频资产。历史自动复制的 MP3 只有完整 SHA-256 匹配才清理；真实用户文件保留。
- WAV/CUE 使用实际文件头、CUE 帧边界与准确末轨结束时间，支持嵌套目录、UTF-16 和 APFS 文件名。
- 重扫串行执行并事务保存，失败保留原曲库；修复误删其他专辑 CUE、共享母带和 ID 重用问题。
- iOS 公共音乐目录统一为 App 的 Documents（文件 App 的“我的 iPhone / HiFi Player”）。WiFi 上传保留专辑目录，并防止覆盖数据库或逃逸目录。
- DAC 显示真实系统路由与协商速率；DX1 II 采样偏好由 iOS 请求并读回验证。音色通过明确标注的 10 段 DSP 映射叠加 EQ，分别保留设置。
- 硬件看板只显示系统可读取的内存、核心数、存储、热状态及电池信息；不再随机模拟指标，也不把系统 PCM 混音标成已验证 BitPerfect。
- Web 遥控真正触发扫描，报告成功或失败；DAC 广播不再递归刷新。

## 第二轮：方向、整页滚动与 iPhone DAC 探测

基线：`dev/iphone` 5226af5。

- 横屏固定为 `landscapeRight`，冷启动仍先选择方向，本次运行中保持锁定；等待原生视口完成旋转后再挂载工作台。
- 两侧外边距收至 4 点，保留刘海及 Home Indicator 安全区。EQ 的“复原／EQ 已旁路”和 Web／WiFi 切换位于标题右侧。
- DAC、EQ、调音、扫描、主题、设置、Web 遥控和 WiFi 传歌共 8 个模块在 iPhone 上使用整页滚动，标题、操作、设备卡与正文共用滚动位置；其他平台保留既有固定标题行为。
- DAC 页面进入时先激活 iOS 音频会话，再读取 `AVAudioSession.currentRoute`。每 2 秒实际查询系统路由，支持插拔与回到前台刷新；手动探测显示当前 USB 输出或明确失败原因，不再只重复发布缓存。查询失败清除过期设备，重试可恢复。
- 原生桥接补充输出端口、传输类型、声道、缓冲、延迟、会话类型及路由变化原因；没有修改 C++ 音频引擎。
- 硬件大师补充独立采集的 App CPU、物理内存空闲、App 内存占用／驻留／可用额度、设备信息、低电量模式及真实音频参数。未开放或读取失败的指标显示原因；模拟器明确标注 CPU／内存／存储来自宿主 Mac。采集失败保留上次成功数据，退出后停止监测。
- 新增随包隐私清单，声明本地 CPU 采样计时和磁盘容量展示的必要 API 用途。

## 第三轮：DSD 噪声、会话时序与预设双列

基线：`dev/iphone` 996b98b。用户确认上一轮已安装完整新包，但播放时仍走扬声器，且控制中心没有 DX1 II；此问题不能归因于只更新了 Dart 或页面显示缓存。

- 修复确定存在的会话竞态：原先未等待的停用可迟于下一次激活完成；现在激活、停用、偏好及路由读取串行，并先停原生音频，再停用会话。手动探测重新核验激活，停用失败可诊断且可恢复。
- iPhone 使用 `playback/default/longFormAudio` 音乐共享路由，初始化策略与运行时一致。移除激活后自动强制请求 256 帧缓冲，保留系统实际协商值。[Apple QA1631](https://developer.apple.com/library/archive/qa/qa1631/_index.html) 指出活动会话修改 I/O 偏好可能停止并重启 I/O。
- 添加原生系统输出选择器及“复制音频诊断”。原生桥 v3 记录真实端口、会话策略、最近路由变化；Dart 记录激活前、激活后、采样率偏好请求后和原生播放开始后的快照。选择器仅展示系统提供的选项，不能保证枚举或强制选择 USB DAC。
- 修复 iPhone DSD→PCM 路径：旧解码器在抗混叠不足时直接抽取 1-bit DSD，会产生可闻噪声。新增 iPhone 专用 FIR 解码器，先滤波再抽取为 176.4 kHz Float32 PCM，之后由已有 CoreAudio SRC 转到实际输出格式；同时修复新路径的单声道写入、DSF 位序、DFF 交错、填充尾部和跳转历史。
- 引擎提交 `9ae3840cc56ed1ef7614546c521d8d43995756db` 已推送到 `dev/audio_engine`，仅 iPhone 分支更新 lock。播放工厂测试证明仅 `iphone` 使用新解码器，其余六种客户端仍用原 `DsfParser`；该旧实现未改。
- 左侧安全留白上限增至 16 点，加外距 8 点；右侧去掉额外 4 点，完整保留刘海安全区。iPhone 横屏主题预设固定每行两项，全部九项名称和说明可读；其他平台保留原布局。

### 第三轮验证与剩余边界

- Flutter 全套 188 项通过（含 13 张 golden），静态检查和 `git diff --check` 通过。
- 引擎 5/5 项测试及新增 DSD 路径的 ASan／UBSan 检查通过。覆盖 DSF 两种位序、DFF、mono、DSD64/128/256/512、精确 EOF、seek、截断输入与七种客户端路径隔离。
- 合成 1 kHz DSD64 转为 48 kHz PCM 的信噪比从旧路径约 32.15 dB 提升到新路径 66.99 dB；合成 100 kHz 超声信号在新路径实际 48 kHz 输出的 RMS 为 −83.00 dBFS。数据来自生成的测试信号，不代表用户所有曲目的真机听感验收。
- 新引擎完整 iOS 模拟器 Debug、未签名真机 Release 构建均通过。iPhone 13 / iOS 26.5 模拟器实际读取原生桥 v3、共享路由策略和系统缓冲；DSF 测试文件成功经新引擎解码为 48 kHz 系统 PCM，激活前后及播放后快照记录正常。主题双列与边距已截图核对，测试音频已删除并重扫为空库。

- Mac、树莓派、iPad 等平台分支及其锁定版本未修改或推送。
